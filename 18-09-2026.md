## 🧠 1. How to Train an LLM from Scratch

I learned about the major stages involved in training an LLM.

### 🔹 Pre-training

**What I learned:**
Pre-training means training an LLM on a huge amount of text so that it learns language patterns, grammar, facts, and relationships between words and concepts.

**Practical example:**
Suppose we train a model on millions of books, articles, websites, and documents. During training, the model sees:

> "The capital of France is ___"

It learns that **"Paris"** is a highly probable continuation.

The model is not manually given a rule saying "France → Paris." Instead, it learns patterns from large amounts of data.

---

### 🔹 Instruction Fine-Tuning

**What I learned:**
Instruction fine-tuning teaches the model how to follow instructions and produce useful responses.

**Practical example:**

Before instruction fine-tuning:

> User: "Explain photosynthesis."

The model may simply continue the text with something statistically likely.

After instruction fine-tuning:

> User: "Explain photosynthesis in simple words."

> Model: "Photosynthesis is the process by which plants use sunlight, water, and carbon dioxide to make food and release oxygen."

The model has learned to treat the input as an **instruction** and respond accordingly.

---

### 🔹 Preference Fine-Tuning

**What I learned:**
Preference fine-tuning teaches the model which types of responses are preferred over others.

**Practical example:**

Suppose the model generates two answers:

**Response A:**

> "Photosynthesis is a biochemical process involving..."

**Response B:**

> "Photosynthesis is how plants use sunlight to make their food."

For a beginner asking for a simple explanation, a human evaluator might prefer **Response B** because it is clearer and more appropriate.

Preference training helps the model learn these kinds of preferences.

---

### 🔹 Reasoning Fine-Tuning

**What I learned:**
Reasoning fine-tuning focuses on improving the model's ability to solve problems that require multiple reasoning steps.

**Practical example:**

> If a notebook costs ₹50 and I buy 3 notebooks, how much do I pay?

The model needs to reason:

> ₹50 × 3 = ₹150

For more complex problems, the model may need several intermediate reasoning steps before reaching the answer.

# ⚙️ 2. How LLMs Work During Text Generation

## 🔹 Conditioning

**What I learned:**
LLMs use the previous context to predict what token should come next. This is called **conditioning**.

**Practical example:**

If we give the model:

> "The sun rises in the"

The model considers the context and may assign a high probability to:

> "east"

If we instead provide:

> "I ate a bowl of"

The likely next tokens could include:

> "rice", "cereal", "soup", etc.

The previous context changes the probability distribution for the next token.

---

## 🔹 Probability of the Next Token

An LLM doesn't simply "know" one guaranteed next word. It produces probabilities for possible next tokens.

For example:

> "The cat is sitting on the ___"

A simplified probability distribution could look like:

| Token | Probability |
| ----- | ----------: |
| mat   |         45% |
| floor |         25% |
| chair |         15% |
| table |          8% |
| bed   |          7% |

The generation strategy then determines how one of these tokens is selected.

---

## 🌡️ Temperature

**What I learned:**
Temperature controls how much randomness or variation is introduced into token selection.

### Low temperature

The model strongly prefers high-probability tokens.

**Example:**

> "The capital of India is..."

Likely output:

> "New Delhi"

This is useful when we want **consistent and predictable answers**.

### Higher temperature

The probability distribution becomes flatter, allowing less-probable tokens to be selected more often.

**Example:**

Prompt:

> "Write a creative story about a robot."

A higher temperature can produce more varied and unexpected wording.

So:

* **Low temperature → predictable output**
* **High temperature → more varied output**

# 🎛️ 3. LLM Generation Parameters

## 1. Maximum Length

**What I learned:**
Maximum length limits how many tokens the model can generate.

**Practical example:**

If we ask:

> "Explain machine learning."

With a small maximum output length, we might get:

> "Machine learning is a method where computers learn patterns from data."

With a larger maximum length, the model can provide a much more detailed explanation with examples.

---

## 2. Temperature

**Practical example:**

Prompt:

> "Give me a name for a coffee shop."

With a low temperature, the model might consistently produce names such as:

> "Morning Brew"

With a higher temperature, it may generate more unusual names such as:

> "MoonBean Café"

Temperature therefore affects **variation in generated responses**.

---

## 3. Top-P / Nucleus Sampling

**What I learned:**
Top-P sampling selects tokens from the smallest group whose combined probability reaches a specified threshold.

**Practical example:**

Suppose the model predicts:

| Token | Probability |
| ----- | ----------: |
| mat   |         50% |
| floor |         25% |
| chair |         15% |
| table |          5% |
| bed   |          5% |

If **Top-P = 0.90**, the model considers:

> mat + floor + chair = 90%

The lower-probability tokens outside that probability mass are excluded.

This allows some variation while avoiding extremely unlikely tokens.

---

## 4. Frequency Penalty

**What I learned:**
Frequency penalty reduces the likelihood of repeatedly generating tokens that have already appeared many times.

**Practical example:**

Without a frequency penalty:

> "The dog was happy. The dog was happy. The dog was happy..."

With a frequency penalty, the model has more incentive to vary its wording:

> "The dog was happy. It wagged its tail and happily ran around the garden."

This can help reduce excessive repetition.

---

## 5. Presence Penalty

**What I learned:**
Presence penalty discourages the model from repeatedly using tokens that have already appeared and encourages introducing new tokens/topics.

**Practical example:**

Suppose we ask:

> "Talk about technology."

Without much penalty, the model may repeatedly discuss:

> technology → technology → technology

A higher presence penalty can encourage the model to introduce related concepts such as:

> AI, robotics, software, cybersecurity, automation, etc.

---

## 6. Stop Sequences

**What I learned:**
A stop sequence tells the model to stop generating when a particular sequence appears.

**Practical example:**

Suppose we want the model to generate a single answer:

> User: "What is Python?"

We could use a stop sequence such as:

> `###`

The model might generate:

> "Python is a high-level programming language.###"

Generation stops when `###` is reached.

This is useful when building structured applications where we need clear boundaries between generated sections.

---

## 7. Top-K Sampling

**What I learned:**
Top-K sampling limits the model's choices to the **K most probable tokens**.

**Practical example:**

Suppose the model predicts:

| Token | Probability |
| ----- | ----------: |
| mat   |         40% |
| floor |         25% |
| chair |         15% |
| table |         10% |
| bed   |          5% |
| roof  |          3% |
| car   |          2% |

If **Top-K = 3**, the model only considers:

> mat, floor, chair

The other tokens are excluded from sampling.

# ✍️ 4. LLM Text Generation Strategies

## 🔹 Greedy Decoding

**What I learned:**
Greedy decoding always chooses the token with the highest probability.

**Practical example:**

If the model predicts:

> mat → 50%
> floor → 30%
> chair → 20%

Greedy decoding always selects:

> **mat**

It is simple and deterministic, but it can sometimes produce repetitive or less creative text.

---

## 🔹 Multinomial Sampling

**What I learned:**
Instead of always choosing the highest-probability token, multinomial sampling randomly selects a token according to its probability.

**Practical example:**

If:

> mat → 50%
> floor → 30%
> chair → 20%

Then:

* mat has a 50% chance of being selected
* floor has a 30% chance
* chair has a 20% chance

This introduces randomness and can make generated text more diverse.

---

## 🔹 Beam Search

**What I learned:**
Beam search keeps multiple possible sequences instead of committing to only one token at every step.

**Practical example:**

Suppose the prompt is:

> "The boy went to the..."

The model might consider:

1. **The boy went to the school...**
2. **The boy went to the park...**
3. **The boy went to the store...**

Instead of immediately selecting one path, beam search keeps several candidate sequences and evaluates them as generation continues.

This can be useful when we want a high-probability sequence rather than purely random generation.

---

## 🔹 Contrastive Search

**What I learned:**
Contrastive search tries to balance selecting probable tokens with avoiding repetitive text.

**Practical example:**

Suppose an LLM starts generating:

> "The city was beautiful. The city was beautiful. The city was beautiful..."

A generation method that considers repetition can avoid repeatedly selecting the same patterns.

Contrastive search attempts to produce text that is both **likely and diverse**, reducing unwanted repetition.

---

# 🔍 5. Self-Evaluation

**What I learned:**
Self-evaluation means using an LLM to evaluate or critique a generated response according to specific criteria.

**Practical example:**

Suppose an LLM generates an answer to:

> "Explain neural networks to a beginner."

We can then ask another LLM evaluation step:

> "Evaluate this answer for correctness, clarity, and whether it is understandable for a beginner."

The evaluator might identify:

* The explanation is technically correct.
* One concept is too complicated.
* An example would make the explanation clearer.

We can then use this feedback to improve the response.

# 💡 Key Takeaway

Today I understood that **LLMs are not only about training a model**.

The complete process involves:

**Pre-training → Fine-tuning → Generation → Sampling/Decoding → Evaluation**

I also learned that generation parameters such as **temperature, Top-P, Top-K, frequency penalty, presence penalty, maximum length, and stop sequences** can significantly influence how an LLM produces its output.

The main thing I learned today is that **the same LLM can produce very different outputs depending on how we configure its generation process and which decoding strategy we use.**
